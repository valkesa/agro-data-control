AgroData UI Templates — Etapa 1

Documento de consulta para definir el contrato funcional del sistema de templates de UI de AgroData antes de avanzar con la implementación.

1. MetricDefinition

Define qué dato representa una métrica.

MetricDefinition
- key
- label
- unit
- icon
- sourceField
- displayType
- decimals

Ejemplo

key: tempInterior
label: Temperatura interior
unit: °C
icon: thermometer
sourceField: tempInt
displayType: number
decimals: 1

Tipos iniciales de displayType

number
percentage
counter
boolean
status
text

2. IndicatorDefinition

Representa información secundaria asociada a una métrica.

IndicatorDefinition
- key
- sourceField
- icon
- condition
- position

Ejemplo

key: calefaccionEtapa1
sourceField: heatStage1
icon: flame
condition: true
position: belowValue

Para la segunda etapa de calefacción se usaría otro indicador equivalente.

0...N indicators
Idea central: los dos fueguitos de Temperatura Interior no se hardcodean como excepción. Se modelan como dos indicadores asociados a la métrica.

3. BoardSlot

Define cómo una métrica se ubica en la vista TABLERO.

BoardSlot
- metricKey
- position
- size
- visible
- indicators[]

size

Inicialmente:

large
medium
small

Esto describe el tamaño del slot, no el template entero.

position

No se usarían coordenadas pixeladas. La posición sería abstracta:

1
2
3
4
...

El layout interpreta qué significa cada posición. Esto permite adaptar el diseño responsive sin cambiar la configuración del template.

4. TableColumn

Define cómo una métrica aparece en la vista TABLA.

TableColumn
- metricKey
- order
- width
- visible
- indicators[]

Ejemplo

metricKey: tempInterior
order: 4
width: medium
visible: true

El icono, la leyenda, la unidad y el formato provienen de MetricDefinition, por lo que no se duplican.

5. DeviceTemplate

Es el objeto central que vincula la definición de métricas con las vistas TABLERO y TABLA.

DeviceTemplate
- id
- name
- boardPreset
- boardSlots[]
- tableSection
- tableColumns[]

Ejemplo: Laboratorio

id: laboratory_basic
name: Laboratorio básico

boardPreset: compact

boardSlots:
- tempInterior
- humedadInterior

tableSection: Laboratorio

tableColumns:
- tempInterior
- humedadInterior

6. Presets de TABLERO

Se mantienen tres presets iniciales:

large
medium
compact

Estos presets determinan la geometría disponible.

large
→ hasta 13 posiciones

medium
→ aproximadamente 5-7 posiciones

compact
→ aproximadamente 2-3 posiciones

No conviene fijar un máximo rígido hasta diseñar las geometrías concretas.

7. Regla de no duplicación

No conviene repetir label, icon y unit dentro de BoardSlot y TableColumn.

La relación correcta es:

BoardSlot
   ↓ metricKey
MetricDefinition
   ↓
label / icon / unit

Y para tabla:

TableColumn
   ↓ metricKey
MetricDefinition

Solo tendría sentido habilitar un labelOverride más adelante si aparece una necesidad real.

8. Ejemplo completo: Temperatura Interior

MetricDefinition

key: tempInterior
label: Temperatura interior
unit: °C
icon: thermometer
sourceField: tempInt
displayType: number
decimals: 1

Indicators

- calefaccionEtapa1
- calefaccionEtapa2

BoardSlot

metricKey: tempInterior
position: 1
size: large
indicators:
- calefaccionEtapa1
- calefaccionEtapa2

TableColumn

metricKey: tempInterior
order: 4
indicators:
- calefaccionEtapa1
- calefaccionEtapa2

Resultado: los mismos dos indicadores de calefacción pueden aparecer tanto en Tablero como en Tabla sin lógica específica para Sala1 o Sala2.

9. Objetivos de la Etapa 1

  1. Definir los tipos permitidos de métricas.
  2. Definir las propiedades definitivas de MetricDefinition.
  3. Definir las propiedades de IndicatorDefinition.
  4. Definir los tamaños de slot.
  5. Definir los tres presets de layout.
  6. Definir las reglas de posición y orden.

10. Punto pendiente a resolver

Falta decidir cómo manejar los colores y estados visuales.

Ejemplo: una temperatura puede verse verde, blanca o en alarma. Hay que definir si esta lógica forma parte del sistema de templates o continúa dependiendo de la lógica de alarmas existente.
